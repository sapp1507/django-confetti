## Результаты команд

### Тесты

Команда:

```bash
pytest -q
```

Результат: 23 теста собрано, 22 прошли, один завершился ошибкой.

Падение:

```text
tests/test_api_core.py::test_edit_not_editable
assert get('edit') == False
AssertionError: assert True == False
```

Причина падения: тест исходил из неверного контракта. Для bool-определения
`enabled` является основным переключателем, поэтому
`SettingDefinition.save()` намеренно синхронизирует `default` с
`enabled=True`. Исправлению подлежит ожидание теста, а не эта синхронизация.

Pytest также сообщает о неизвестной опции `DJANGO_SETTING_MODULE` в
`pytest.ini`. Корректное имя — `DJANGO_SETTINGS_MODULE`.

### Django system check

Команда:

```bash
python manage.py check
```

Команда завершилась с кодом 0 и двумя предупреждениями `fields.E010`:

- `SettingDefinition.default` использует изменяемый `default=[]`;
- `SettingDefinition.choices` использует изменяемый `default=[]`.

### Проверка миграций

Команда:

```bash
python manage.py makemigrations --check --dry-run
```

Результат: `No changes detected`. Команда завершилась с кодом 0 и повторила
два предупреждения `fields.E010`.

## Защищаемая совместимость версии 0.4.2

При последующих исправлениях регрессионные тесты должны защищать:

1. Публичный Python API: `get`, `set_value`, `is_enabled` и их существующие
   параметры.
2. Приоритет user → global → definition default → caller default.
3. Конфигурацию `settings.CONFETTI` и импорт `RESPONSE_METHOD` по строке.
4. Существующие модели, имена полей и значения enum.
5. REST URL, имена маршрутов и структуру успешных ответов.
6. Management-команды `confetti_seed` и `confetti_sync`.
7. Чтение snapshots формата версии `0.4.2`.
8. Обновление существующей БД через последовательные Django migrations.

Подтверждённые дефекты не считаются контрактом совместимости автоматически.
Однако их исправление должно быть минимальным, проверяться отдельным тестом и
не менять соседнее корректное поведение.
